# 遥测 UDP 代理（接收器 A/B 切换）

遥测终端经 UDP 代理把短报文发给接收器，值班员在网页上切换接收器 A/B，
已建立的会话不受影响，回包不会送错设备。

## 组成

| 组件 | 说明 |
|---|---|
| `proxy/` | asyncio UDP 代理 + Flask 操作网页 + SQLite 持久化 |
| `receiver/` | 本地接收器，原样回显报文，可延迟回包 |
| `docker-compose.yml` | 一键启动代理 + 接收器 A + 接收器 B |
| `scripts/verify_local.py` | 无 Docker 环境下的端到端行为验证 |
| `scripts/verify_shadow.py` | 无 Docker 环境下的影子校验行为验证 |

## 启动

```bash
docker compose up --build
```

- 操作网页：http://localhost:8080
- 遥测终端发送地址：`UDP <宿主机>:9000`

## 行为规则

- **会话**：按客户端 `IP:端口` 建立，空闲 5 秒（`SESSION_IDLE_TIMEOUT`）无收发即过期。
- **建会话时固定接收器**：会话期间的一切报文都发往建会话那一刻的目标接收器；
  网页切换 A/B 只影响之后新建的会话，旧会话继续走原接收器直到过期。
- **原样透传**：报文与回包内容不做任何修改。
- **回包不错投**：每个会话使用一条独立的、已 connect 到其接收器的上游 UDP
  套接字（独立本地端口），只有该会话对应接收器的回包会被送回该客户端。
- **迟到回包**：会话过期即关闭其上游端口，端口进入冷却期
  （`UPSTREAM_PORT_COOLDOWN`，默认 30 秒，应大于最大回包延迟）不再分配；
  因此相同 `IP:端口` 重建的新会话也不可能收到旧会话迟到的回包。
- **切换可靠性**：切换先写 SQLite 再生效，保存失败保留原目标并在网页报错。
- **重启**：目标接收器保存在 SQLite（`proxy-data` 卷）重启后保留；
  会话全在内存，重启即清空。

## 影子校验（切流前试跑）

切换接收器前，值班员可在网页点击“开启 10 秒影子校验”，再发送试传报文建立新会话。
代理会把该会话的前 16 条上行原文同时发往固定接收器与另一台接收器，网页统计两侧
回包原文及次数并给出结论，便于在真正切流前确认两台接收器行为一致。

规则：

- **窗口与绑定**：开启后 `SHADOW_WINDOW`（默认 10 秒）内新建的**第一个**会话被绑定为
  影子会话；已有会话不受影响，也不参与本次校验。
- **两侧固定**：本次比较的两侧在开启时即确定（当前目标为“固定侧”，另一台为“影子侧”）。
  期间切换目标只影响之后的新会话，不会改变本次校验正在比较的两侧；影子会话本身也仍
  固定走开启时的固定侧。
- **只下发固定侧**：影子侧回包只做统计，绝不发给终端；终端行为与未开启校验时完全一致。
- **比较口径**：按“回包原文 + 每条原文的出现次数”做多重集合比较。
  到达顺序不同、同文重发都不会误判。
- **结论**：
  - `一致`：两侧回包原文与次数完全一致；
  - `差异`：两侧都收到回包，但原文/次数不一致（网页列出各自独有的回包）；
  - `证据不足`：任一侧缺包、镜像发送失败、超过 16 条上行（多出的报文未纳入比较）、
    窗口内未建立会话，或校验总时长超限。
- **多出的报文**：绑定会话第 17 条及以后的上行仍按原规则只走固定侧透传，
  同时计入证据不足的依据，不再镜像。
- **停止镜像与隔离**：校验结束（手动/会话空闲过期/重启/总超时）即关闭镜像套接字；
  每次校验有唯一编号，迟到回包只会被丢弃，不会串入下一次校验。
- **收尾**：网页手动结束时，若仍有在途回包，会在 `SHADOW_DRAIN`（默认 1 秒）内等待
  收齐后再定稿；两侧回包本就齐全时立即定稿。

演示差异：在 compose 中给接收器 B 设置 `REPLY_TEMPLATE: "B:{payload}"`（或任意
`REPLY_PREFIX`），使其返回与固定侧不同的内容，再开启校验即可看到“差异”。

## 网页功能

- **切换目标接收器**：一键切换 A/B。
- **影子校验**：开启/结束校验，实时查看已镜像条数、两侧回包原文与次数、结论与依据。
- **发送试传报文**：可设置回包延迟（秒）、固定客户端端口、等待超时；
  结果显示实际去向接收器、回包内容与 RTT。
  - 不填端口：每次试传都是新会话（走当前目标）。
  - 填同一端口：空闲 5 秒内复用旧会话（仍走旧接收器）；
    配合"回包延迟 > 5 秒"可现场观察旧会话迟到的回包被丢弃。
  - 做影子校验时建议不填端口，让试传新建会话并被校验绑定。
- **活动会话 / 报文日志**：实时查看每个会话固定的接收器、是否绑定影子校验、每条报文的
  实际去向与回包（每 2 秒自动刷新）。影子回包在日志中方向显示为“影子回包（仅比较）”。

## 接收器延迟回包与自定义回包

- 环境变量 `REPLY_DELAY`：该接收器所有回包的默认延迟秒数。
- 报文级覆盖：报文以 `DELAY:<秒>:` 开头时按该值延迟（回包仍是完整原始报文）。
- 环境变量 `REPLY_TEMPLATE`：自定义回包内容，`{payload}` 替换为原始报文
  （例如 `"B:{payload}"`）；未设置时原样回显。
- 环境变量 `REPLY_PREFIX`：在原始报文前加前缀的便捷写法（等价 `"{前缀}{payload}"`）。

## 配置（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `UDP_LISTEN_PORT` | `9000` | 代理对终端的 UDP 监听端口 |
| `HTTP_PORT` | `8080` | 操作网页端口 |
| `SESSION_IDLE_TIMEOUT` | `5` | 会话空闲超时（秒） |
| `RECEIVER_A_HOST/PORT`、`RECEIVER_B_HOST/PORT` | 见 compose | 接收器地址 |
| `DB_PATH` | `/data/proxy.db` | SQLite 路径（目标持久化） |
| `UPSTREAM_PORT_MIN/MAX` | `20000/29999` | 上游本地端口池 |
| `UPSTREAM_PORT_COOLDOWN` | `30` | 上游端口关闭后的冷却秒数 |
| `SHADOW_WINDOW` | `10` | 影子校验绑定新会话的窗口（秒） |
| `SHADOW_LIMIT` | `16` | 每个影子会话最多比较的上行条数 |
| `SHADOW_DRAIN` | `1` | 手动结束校验后的收尾等待（秒） |
| `SHADOW_MAX_DURATION` | `75` | 单次校验总时长上限（秒） |

## 本地验证（无需 Docker）

```bash
pip install flask
python3 scripts/verify_local.py
python3 scripts/verify_shadow.py
```

`verify_local.py` 逐项验证：原样透传（含二进制）、切换后旧会话走原接收器、过期后新会话走
新接收器、迟到回包不投递、网页试传、重启保留目标并清空会话、保存失败保留原目标。

`verify_shadow.py` 逐项验证影子校验：两侧回包一致/差异、乱序与同文重发不误判、
缺包与超过 16 条为证据不足、多出的报文仍透传、切换不改变比较两侧、迟到回包不串入
下一次、重启后不残留校验。
